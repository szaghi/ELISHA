# L0: the solvers' math

The first layer of ELISHA: pure procedures of integers and spacings. They hold no state and call neither MPI nor an
FFT library. The spectral solver calls them once per setup. They come from ADAM's `adam_poisson_fft_object` (ADAM
669d0bdd) and are held to it bitwise by a test (`elisha_test_adam_parity_l0`, 933907 checks).

```fortran
use elisha, only : ELISHA_BC_DIRICHLET, ELISHA_BC_NEUMANN, elisha_axis_eigenvalue, elisha_axis_transform_size, &
                   elisha_axis_map, elisha_dg_stencil, elisha_smooth_size, elisha_lattice_green
```

## Boundary kinds

Each face of the domain has a kind, `bc(2,3)` = [low/high, axis]. The values are ADAM's `FLAIL_BC_*`, so an ADAM
adapter passes them through unchanged.

| Kind | Meaning | Homogeneous ghost |
|------|---------|-------------------|
| `ELISHA_BC_PERIODIC` | Periodic axis (both faces) | the wrapped cell |
| `ELISHA_BC_DIRICHLET` | Value at the face | `-phi_boundary` |
| `ELISHA_BC_NEUMANN` | Normal derivative at the face | `+phi_boundary` |
| `ELISHA_BC_DIRICHLET_GHOST` | Value at the first ghost centre (the multigrid's root) | `0` |
| `ELISHA_BC_ZERO_GHOSTS` | Every ghost layer zero (wide D(G): CG) | `0`, every layer |
| `ELISHA_BC_FREE_GHOSTS` | Ghosts hold the free-space potential (wide D(G)) | the potential |

## Transform sizes and extensions

The spectral solver turns face kinds into a periodic problem. It extends the source over the axis's transform cells
and transforms the extension. `elisha_axis_transform_size(n, ngc, bc, isolated, pcg, null)` gives the number of
cells:

| Axis | Transform cells | Extension |
|------|-----------------|-----------|
| Periodic, null, or the CG path | `n` | none |
| Dirichlet/Neumann, the same at both faces | `2n` | odd (Dirichlet) or even (Neumann) about each face |
| Dirichlet/Neumann, different faces | `4n` | the quarter-wave extension |
| Ghost-Dirichlet | `2 (n + 1)` | odd about the ghost centres (type-I sine transform) |
| Isolated | `elisha_smooth_size(2 (n + ngc))` | zero padding |

`elisha_axis_map(n, m, bc, isolated, t, src, sg)` gives the source cell of each target cell `t` and its sign
(`src = -1` for a zero). `elisha_set_plane` applies the map to a plane of a 3-D array.
`elisha_smooth_size(k)` returns the smallest even size at or above `k` with no prime factor above 13. FFTW has
hard-coded transforms for these factors (ADAM #84 E5b: 262 = 2 x 131 cost 3.3 times as long as 264).

## Eigenvalues

Mode `k` of an axis transformed over `nt` cells, with `theta = 2 pi k / nt`:

| Operator | `elisha_axis_eigenvalue(k, nt, dx, p)` |
|----------|----------------------------------------|
| Compact 3-point (`p = 0`) | `(2 cos(theta) - 2) / dx^2` |
| Wide D(G) of order `p` = 2, 4, 6, 8 | `-s_p(theta)^2 / dx^2`, `s_p(theta) = sum_j 2 a_j sin(j theta)`; exactly 0 at `theta` = 0 and pi |

The `a_j` are the centred first-derivative coefficients (`ELISHA_D1_COEF`). A test holds them bitwise equal to
GIDEON's generated rows. `elisha_dg_stencil(p)` is the 1-D stencil of D1 D1 times h^2, offsets -p..p.
`elisha_test_spectral` checks these by their meaning, in exact integers:
- the D1 order conditions;
- the stencil moments (0, 2, 0, …);
- that each eigenvalue equals its stencil's symbol.

## Lattice Green's function

`elisha_lattice_green(n)` returns `G(n)`, the solution of `L_1 G = delta_(n,0)` with `G -> -1/(4 pi |n|)`: the
kernel of the isolated spectral solver. On a lattice of spacing `h` the kernel is `h^2 G`. Within `max |n_d| <= 32`
the value comes from a table; beyond, from the asymptotic expansion `G0 + G1 + G2 + G3`.

| Check | Value |
|-------|-------|
| `max abs(L_1 G - delta)` on [-63, 63]^3, across the table/expansion faces | 1.06e-13 |
| `G(0)` against Watson's closed form | 2e-13 relative |
| Against ADAM's `lattice_green` on [-70, 70]^3 | bitwise |

The module is generated by ADAM's generator, `scripts/lattice_green.py`. Do not edit it by hand. `--check`
compares it with a fresh emission, and `--flavour adam` emits ADAM's module. The values are pinned to ADAM's
committed table (`--from`, the test oracle), because the emission is not bitwise reproducible across numpy/OpenBLAS
builds. With numpy 2.5.1 and OpenBLAS 0.3.33, a fresh table differs by at most 1.4e-15 relative, and the fitted
far-field coefficients by up to 4e-11. Every check of the generator still passes.
